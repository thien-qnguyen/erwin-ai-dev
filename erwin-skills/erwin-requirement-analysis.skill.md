# Erwin Requirement Analysis Skill

## Purpose

Convert an incoming development request into a precise, testable understanding before implementation.

## Use When

Use near the beginning of a development task, regardless of whether the source is an issue tracker, document, chat request, bug report, feature request, or maintenance task.

## Method

1. Identify requested behaviour and expected outcome.
2. Extract explicit acceptance criteria when present.
3. Infer only what is necessary; mark inferred items as assumptions.
4. Separate requirements from implementation suggestions supplied by the requester.
5. Identify explicit constraints and non-goals.
6. Identify material ambiguity that could change implementation behaviour.
7. Produce a concise requirement checklist suitable for later reconciliation.

## Output

- Goal
- Expected behaviour
- Acceptance criteria
- Constraints
- Non-goals
- Assumptions
- Open questions, only when materially blocking
